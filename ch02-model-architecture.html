关于「Transformer」一词的两种含义

本章讲解的是 Transformer 架构，即模型本身的结构；而 HuggingFace 的 transformers 是一个软件库，是验证这些原理的工具。二者名称相近但所指不同。

另需说明，本章讲的并非 2017 年原始论文中的 Transformer。原论文的编码器-解码器结构、正弦位置编码、LayerNorm 后置、ReLU 前馈网络与多头注意力，在现代大模型中已分别被仅解码器结构、RoPE、RMSNorm 前置、SwiGLU 与 GQA 取代。真正保留下来的只有两样：缩放点积注意力的核心形式，以及残差连接与归一化的堆叠方式。因此建议直接阅读现代实现，而非从原始论文入手。

2.0一次前向的全景

在进入各个部件之前，先建立整体的数据流认识，否则后续内容会显得零散。一次前向计算的流程如下：token id 序列经嵌入层查表得到向量表示，依次通过若干个结构相同的层，最后经归一化与输出层得到词表上的分布。

整个模型中带参数的部件只有三类：嵌入层、每一层内部的注意力与前馈网络、输出层。其余部分——RMSNorm、softmax、激活函数、RoPE 旋转——均不含参数，且浮点运算量占比极低。需要注意的是，这些操作虽然算力开销小，却大多是带宽受限的，因此在内核融合中仍具有实际意义，这一点将在第五章讨论。

本章将反复使用以下这组分布作为主线，后续每一节都在解释它的成因：

部件参数量占比
前馈网络（80 层合计）56.37 B79.9%
注意力（80 层合计）12.08 B17.1%
嵌入层与输出层2.10 B3.0%
合计70.55 B100%

2.1分词器

分词器负责将文本切分为整数 id 序列。主流实现为字节级 BPE：从单字节出发，反复将出现频率最高的相邻符号对合并为新符号，合并 V 次即得到规模为 V 的词表。

从工程角度只需关注三点：

其一，词表规模同时影响两处成本。嵌入层参数量为 V×d，输出层每个 token 的算力为 2·d·V。Llama 3 将词表从 32K 扩大至 128K，嵌入层与输出层的参数量合计从约 0.5B 增至 2.1B，换取的是更高的分词效率。

其二，分词效率直接体现为成本差异。同一段中文文本，不同分词器切出的 token 数可能相差百分之五十以上；代码中的缩进与符号对此更为敏感。在按 token 计费的场景中，这是纯粹的成本差异。

其三，对话模板与特殊 token 是线上故障的常见来源。模型只识别训练时所用的那套模板，<|begin_of_text|>、<|eot_id|> 等标记多一个或少一个，都会导致输出质量明显下降，且通常不会报错。

2.2嵌入与位置编码

嵌入层的本质是查表：将 token id 映射为 d 维向量，参数矩阵形状为 V×d。该操作不含计算，只有一次访存。

为什么必须引入位置编码

注意力机制本身是置换不变的。若将输入 token 的顺序打乱，注意力的输出只是随之改变位置，内容完全相同。也就是说，在不引入位置信息的情况下，模型无法区分「狗咬人」与「人咬狗」。位置编码正是为解决这一问题而存在。

位置编码的演进路线为：

  • 绝对位置编码（正弦函数，2017）：为每个位置生成固定向量，加至嵌入向量上。
  • 可学习位置编码（GPT-2）：将位置向量作为参数训练。其局限在于超出训练长度后没有对应的向量可用。
  • 旋转位置编码 RoPE（当前标准）：不做加法，而是将 Q 与 K 向量按位置旋转相应角度。

RoPE 的核心直觉：将位置 m 处的向量旋转 mθ 角度。两个向量做点积时，旋转角度相减，结果只依赖于相对距离 m−n。由于相对关系具有平移不变性，模型因此获得了外推到未见长度的可能。

长上下文能力主要通过调整 RoPE 实现：增大旋转基频（Llama 3 取 500000）、NTK-aware 插值、YaRN 等方法，本质都是在改变旋转频率的分布。将短上下文模型扩展为长上下文模型，主要改动即在此处。

2.3注意力机制

注意力机制的直观含义是：每个 token 向此前的所有 token 提出查询，按相关程度加权取回信息。为此需要三个投影，各有分工：

投影计算含义
Q queryX @ W_q当前 token 在寻找什么信息
K keyX @ W_k本 token 是什么，供其他 token 匹配
V valueX @ W_v本 token 能够提供的内容
 
scores = Q @ Kᵀ / √d_head      token 两两之间的相关度，形状 S×S
scores = softmax(mask(scores)) 因果掩码：只允许关注自身及左侧
out    = scores @ V            按权重取回内容
out    = out @ W_o             输出投影，混合各头结果

关于缩放系数 √d_head：点积由 d_head 项求和得到，其方差随 d_head 线性增长。若不缩放，当 d_head 取 128 时点积数值会相当大，softmax 将趋于饱和并退化为近似 one-hot 分布，导致梯度消失。

关于多头：将 d = 8192 切分为 64 份、每份 128 维，各份独立完成上述计算后再拼接。其目的是让不同的头关注不同类型的关联——部分头负责语法邻接，部分头负责长距离指代。需要注意的是，这种切分并不增加参数量，Q 投影仍为 8192×8192 的矩阵，只是在使用时按头切开。

本节的成本分析

注意力内部存在两类性质完全不同的矩阵乘法，区分它们是理解后续推理优化的前提：

第一类是四个投影，其中一侧操作数是参数，算力随序列长度线性增长，可用参数量估算。第二类是 QKᵀ 与分数乘 V，两侧操作数都是激活值，不含任何参数，算力随序列长度平方增长。

这正是第一章中 6ND 公式口径说明的来源——该公式只统计了第一类。第二类的实际占比如下（以 Llama-3-70B 的 prefill 为例）：

上下文长度注意力 S² 项参数矩阵乘法额外开销
2K1.10×10¹³2.89×10¹⁴+3.8%
8K1.76×10¹⁴1.16×10¹⁵+15.2%
32K2.82×10¹⁵4.62×10¹⁵+60.9%
128K4.50×10¹⁶1.85×10¹⁶+243.5%

在常见序列长度下该项可以忽略，但在长上下文场景中它会成为主要开销。这解释了 FlashAttention 一类专门优化注意力算子的工作为何具有如此高的价值——在长上下文条件下，它优化的正是主要矛盾。

2.4KV Cache 的由来

本节承接第一章的成本分析，说明 KV Cache 这一机制为何存在。

在 decode 阶段，每生成一个新 token，都需要让它对全部历史 token 计算注意力。但历史 token 的 K 与 V 是不变的——它们只取决于那些 token 自身，与新生成的内容无关。既然如此，计算一次后保存下来即可。

不缓存：每步重算全部 K/V，第 t 步 O(t·d)，生成 S 个 token 累计 O(S²·d)
缓存：  每步只计算新 token 的 K/V，O(d)，累计 O(S·d)
代价：  需要 O(S·d) 的显存常驻
一笔典型的显存换算力交易

KV Cache 以显存占用换取算力节省，是推理系统中最重要的一项设计。而第一章已经算过这笔账的另一面：这部分显存正是并发规模的上限。第三章中的分页管理、前缀缓存与 KV 量化，全部是围绕如何更有效地使用这块显存展开的。

为什么只缓存 K 与 V，不缓存 Q：Q 仅在生成当前 token 时使用一次，用后即无价值；而 K 与 V 会被此后的每一个 token 反复查询。这一区别决定了缓存的内容，也决定了 KV Cache 的容量公式中为何是系数 2。

2.5注意力变体的演进

既然 KV Cache 构成推理瓶颈，而其大小正比于 KV 头数，压缩 KV 头数便成为最直接的手段：

KV Cache / token = 2 × L × H_kv × d_head × sizeof(dtype)
                            ↑ 结构参数中唯一可直接调节的项
方案KV 头数每 token 占用质量影响
MHA 多头注意力64（各头独占）2560 KiB基准
MQA 多查询注意力1（全部共享）40 KiB压缩 64 倍，但质量下降明显
GQA 分组查询注意力8（每 8 头一组）320 KiB压缩 8 倍，质量几乎无损
MLA 多头潜在注意力存低秩隐向量更低DeepSeek 方案，压缩率更高

此处还有一个第一章未展开的连带效应：GQA 同时也减少了 K 与 V 投影的参数量。Llama-3-70B 单层注意力的参数量因此从 MHA 方案的 268.4M 降至 151.0M。

对第一章一处表述的订正

第一章中曾表述为「前馈网络参数量约占模型总参数量的三分之二」，该说法不够准确。正确的数值取决于注意力方案：采用 MHA 的模型约为 72%，采用 GQA 的模型约为 80%。差异正是来自上述连带效应——GQA 压缩了注意力的参数量，前馈网络的占比因而相应上升。

2.6前馈网络与 SwiGLU

为什么需要前馈网络：注意力所做的是对已有向量的加权平均，本质上是一种线性混合，并不产生新的信息。前馈网络提供非线性变换，同时承担知识存储的功能——研究普遍认为模型中的事实性知识主要存储于此。

其结构为升维、非线性、再降维。SwiGLU 使用三个权重矩阵：

FFN(x) = ( Swish(x @ W_gate) ⊙ (x @ W_up) ) @ W_down
                ↑ 门控          ↑ 内容        ↑ 降回 d 维

W_gate, W_up : d × d_ff        W_down : d_ff × d

参数量为 3 × d × d_ff。Llama-3-70B 的 d_ff = 28672，约为 d 的 3.5 倍，因此单层前馈网络参数量为 704.6M，而同层注意力仅为 151.0M。

这即是 79.9% 这一比例的来源。模型的规模主要由前馈网络决定，而非注意力——这一点与多数人的初始判断相反。

2.7归一化与残差连接

残差连接的形式为 x = x + f(x)，其作用是为梯度提供一条直通路径。这是模型能够训练至 80 层深度的前提条件。

RMSNorm 取代 LayerNorm：省去减均值这一步，仅做缩放。计算量更小，效果无损失。

前置归一化取代后置归一化：即将归一化置于子层之前，写作 x + f(Norm(x))。这一改动显著提升了深层网络的训练稳定性，代价是表达能力略有下降。当前的大模型均采用这一方案。

2.8混合专家模型

混合专家模型将前馈网络替换为 N 个专家网络，由路由器为每个 token 选择其中 top-k 个激活。其余专家在本次计算中不参与运算，但仍需常驻显存。

对基础设施规划最关键的一处错位 
推理算力 ∝ 激活参数量      DeepSeek-V3：算力特征接近 37B 模型
显存占用 ∝ 总参数量        DeepSeek-V3：显存特征接近 671B 模型

这一错位决定了混合专家模型的部署形态：显存压力极大，通常需要专家并行将其铺开到多卡；而算力开销相对低廉。它与稠密模型属于完全不同的两类部署问题。

其余需要了解的概念包括路由器的 top-k 选择、共享专家设计，以及用于抑制专家负载不均衡的辅助损失。负载不均衡会导致整体效率受最慢分片制约，这是混合专家模型工程实现中的主要难点。

2.9输出层与采样

输出层是 d → V 的投影，对 Llama-3-70B 而言形状为 8192×128256，参数量 1.05B。其算力开销不容忽视：由于词表规模很大，prefill 阶段若对每个位置都计算，开销相当可观。多数实现只对最后一个位置计算 logits，这是一项常见优化。

采样策略包括贪心解码、温度采样、top-k、top-p 与 min-p，以及重复惩罚与 logit 偏置等控制手段。束搜索在开放式生成任务中已基本被弃用，原因有二：生成结果的多样性不足，且与连续批处理机制不易配合。

2.11本章练习

第一章的验收标准是能够估算并发规模，本章的验收标准是能够从配置文件复原参数量分布。

练习 1 · 参数量核算

Qwen3-32B 的配置为：d = 5120，L = 64，查询头数 64，KV 头数 8，头维度 128，d_ff = 25600，V = 151936。请分别算出注意力、前馈网络、嵌入层与输出层三部分的参数量及占比，并检验总量是否接近标称的 32.8B。

查看解答 
单层注意力 = 5120×8192 + 2×5120×1024 + 8192×5120 =  94.4 M
单层前馈   = 3 × 5120 × 25600                     = 393.2 M
单层合计                                           = 487.6 M
64 层合计                                          =  31.21 B
嵌入层 + 输出层 = 2 × 151936 × 5120                =   1.56 B
总计                                               =  32.76 B  ✓

占比为：前馈网络 76.8%，注意力 18.4%，嵌入层与输出层 4.7%。与 Llama-3-70B 相比，前馈网络占比略低而嵌入层占比略高，原因是该模型的隐藏维度较小而词表规模更大——词表在小模型上的相对成本更高，这一现象在参数量更小的模型上会进一步放大。

练习 2 · 承接第一章的关键一题

2.3 节给出的数据显示，128K 上下文下注意力的 S² 项达到参数矩阵乘法的 2.4 倍。这一开销对 prefill 与 decode 两个阶段的影响是否相同？请说明理由。

查看解答

不相同，二者的性质完全不同。

prefill 阶段：需要一次性计算 S×S 的完整分数矩阵，因此确实付出 S² 量级的算力。表中的数值描述的正是这一阶段——128K 上下文的 prefill，注意力开销超过参数矩阵乘法的两倍，首 token 延迟因此急剧上升。

decode 阶段：每步只生成一个 token，其 Q 只有一行，需要与全部 S 个历史 K 做点积，因此单步的注意力算力是 O(S) 而非 O(S²)。累计生成 S 个 token 才达到 S² 量级。

更关键的是性质差异：decode 阶段该步骤需要读取整个 KV Cache，其计算量与访存量之比很低，属于典型的带宽受限操作。因此在 decode 阶段，长上下文的代价主要不体现为算力，而体现为显存带宽与显存容量。

prefill 长上下文 → 算力问题 → 优化方向：FlashAttention、分块预填充
decode  长上下文 → 带宽与容量问题 → 优化方向：KV 压缩、量化、分页管理

这一区分是第三章全部技术选型的依据：同样是「长上下文很贵」，两个阶段贵在完全不同的地方，因而需要完全不同的解决手段。

练习 3 · 结构改动的连锁影响

若将 Llama-3-70B 的 d_ff 由 28672 降至 14336，其余配置不变。参数量变为多少？KV Cache 是否改变？这一改动对第一章算出的「8K 上下文 22 路并发」有何影响？

查看解答 
单层前馈 = 3 × 8192 × 14336 = 352.3 M      原为 704.6 M
总参数量 = 42.37 B                      原为 70.55 B

KV Cache = 2 × 80 × 8 × 128 × 2 = 320 KiB  完全不变

KV Cache 不变，因为它只取决于层数、KV 头数与头维度，与前馈网络的宽度无关。

但并发规模会显著上升，因为权重占用减少后，留给 KV Cache 的空间变多了：

FP8 权重 42.4 GB → 可用 88.6 GB → 270,000 tokens → 8K 上下文 33 路   原 22 路
BF16 权重 84.7 GB → 可用 46.3 GB → 141,000 tokens → 8K 上下文 17 路  此时可单卡部署

本题的意义在于揭示一条容易被忽视的联系：降低前馈网络宽度不仅减少了权重显存，还间接提升了并发能力。这也说明为何模型结构的选择与推理成本无法分开讨论——第三章中的每一项部署决策，前提都是本章所确立的这些结构参数。

2.12小结

本章内容可归纳为五条：

  1. 带参数的部件只有三类：嵌入层、每层的注意力与前馈网络、输出层。其余部分无参数且算力占比极低。
  2. 前馈网络占参数量的大头（GQA 模型约 80%，MHA 模型约 72%）。模型规模主要由 d_ff 决定。
  3. 注意力内部有两类矩阵乘法：投影随 S 线性增长且含参数，注意力本身随 S² 增长且无参数。后者是 6ND 公式的口径边界。
  4. KV Cache 是一笔显存换算力的交易，其大小正比于 KV 头数，而 KV 头数是结构参数中唯一可直接调节的推理成本项——GQA 的全部价值即在于此。
  5. 混合专家模型造成算力按激活参数、显存按总参数的错位，使其部署形态与稠密模型截然不同。

其中第三条与第四条是本章通向第三章的桥梁。理解了「prefill 与 decode 在长上下文下贵在不同地方」以及「KV Cache 是并发的枷锁」，第三章中分页管理、前缀缓存、分块预填充与 KV 量化等技术的动机便都不需要额外解释。
