导言

本大纲的定位与使用方法

0.1适用读者与视角

本大纲面向具备一定工程基础、希望系统了解大语言模型技术栈的读者，尤其适用于从事推理服务部署、训练平台建设或 GPU 集群运维的工程人员。阅读前应具备 Python 编程能力、Linux 使用经验，以及分布式系统的基本概念。

需要说明的是，本大纲采用系统与平台工程的视角，而非算法研究的视角。因此内容重心在于计算成本的构成、系统瓶颈的定位、工程实现的取舍，对模型效果调优、评测榜单与算法创新的覆盖较为有限。若读者的目标是从事模型算法研究，本大纲可作为系统侧的补充材料，但不适合作为主线。

0.2内容组织

全文分为四个部分。第一部分说明五个模块之间的依赖关系，并给出两条可选的阅读顺序。第二部分为模块详解，按依赖顺序分为五章，每章包含该模块的主题清单，各主题标注为原理、实践或要点三类。第三部分给出一份十二周的学习计划，将各章内容分配至具体周次并明确每周产出。第四部分为参考资料，包含分层的论文清单、已有中文资料的评估，以及针对薄弱环节的补充资源。

其中第三章（推理系统）额外附有一条分为八个阶段的入门路径，供希望优先掌握推理方向的读者使用，其设计意图详见 1.2 节。

0.3使用建议

第一，建议从代码进入，将论文作为解释代码的辅助材料。大语言模型领域的论文数量庞大且更新迅速，脱离实现直接阅读论文，短期内可以积累术语，但难以形成稳定的理解。较为有效的做法是先运行并读懂一份最小实现，再通过论文理解其设计动机。

第二，每完成一章，应当用自己的语言写出该章的核心权衡。本大纲中的每个模块都围绕若干组明确的取舍展开——例如显存与通信的交换、延迟与吞吐的平衡、精度与性能的折中。若无法清晰表述这些取舍，通常说明该章内容尚未真正掌握。

第三，实践环节应尽可能在真实环境中完成。推理与训练的多数问题只在一定规模下才会显现，玩具环境难以复现真实的瓶颈。若读者具备实际的 GPU 集群与线上服务条件，应当充分利用这一优势，将第三章与第四章的实践项目直接部署于真实环境。

1.2两条可选的阅读顺序

本大纲提供两条阅读路径，二者覆盖的内容一致，区别仅在于进入顺序。

完整路径适用于系统性学习，按 M0 至 M4 的顺序依次推进，对应第三部分的十二周计划。该路径的优点是概念铺垫充分，进入每一章时前置知识均已具备；缺点是产出周期较长，前三周主要为概念性内容。

推理优先路径适用于当前工作与推理服务直接相关、希望尽快获得实际产出的读者。该路径先完成 M0 与 M1 中与推理相关的最小子集（约需半天），随后直接进入第三章的入门路径；完成该路径后，再回补 M1 的其余内容与 M3、M4。第三章 3.1 节给出了该路径的详细阶段划分与验收标准，其内容对应十二周计划中的第四至第八周。

选择的依据是产出周期而非难度：两条路径的总工作量相近，推理优先路径将可验证的实践环节前置，因而反馈更快。

覆盖情况分析

主要缺口：第三章推理系统缺乏对应材料。已有的十二份资料中，没有一份涉及推理引擎的实现原理，包括分页注意力、连续批处理、量化与投机解码，以及 vLLM、SGLang 等引擎的源码。对于从事推理服务运维的读者而言，这恰是与日常工作关联最紧密、且具备实践条件的方向，应当优先补充。

次要缺口之一：框架性能工程的深入内容。两份 PyTorch 中文教程均以框架使用为主，未覆盖 torch.compile 的内部机制、Triton 内核编写与 Nsight 性能归因，而这些正是第五章的核心内容。

次要缺口之二：训练基础设施与强化学习系统。已有资料对并行策略的覆盖较为充分，但分布式检查点、容错与弹性训练、慢节点检测，以及推理引擎与训练引擎共存等强化学习训练的系统问题，尚无对应材料。

结语

本大纲的组织依据是各知识点之间的实际依赖关系，而非主题的重要程度。因此建议按既定顺序推进，在前置内容尚未掌握时跳跃阅读，通常会导致后续内容停留在术语层面。

大语言模型的工程实践仍处于快速演进阶段，本大纲中涉及具体框架版本、硬件规格与性能数据的部分会较快过时，而计算成本模型、系统瓶颈的判定方法与各项工程取舍的分析框架则相对稳定。学习时建议将重心放在后者。
