# LLM 系统工程地图

> 从「一个 token 是怎么算出来的」，到「怎么在一批 H200 上把它便宜地算出来」。

**📖 在线阅读：<https://zhuguangbin.github.io/llm-learning-notes/>**

这是我自学 LLM 的知识地图和进度记录。视角是**基础设施 / 平台工程**，不是算法研究——所以权重压在推理引擎、分布式训练系统、PyTorch 性能工程上，刷榜和调参基本不写。

前置：Python、Linux、分布式系统基础。

## 结构

六个模块按**依赖顺序**排列，不是按主题排列——这几块之间的先后是真的：

```
 地基   M0 算术底座  ──  M1 模型原理
                     │
                     ▼
 主干   M2 推理系统  ‖  M3 训练系统      ← 可并行，我从推理进场
                     │
                     ▼
 横切   M4 PyTorch / CUDA 工程           ← 贯穿两条主干，边学边用
```

| 模块 | 内容 | 一句话 |
|---|---|---|
| **M0** 算术底座 | GEMM 成本模型、数值格式、三个口算公式 | 不是数学课。整个领域 80% 的选型争论都能被三个公式终结 |
| **M1** 模型原理 | Tokenizer、RoPE、MHA→GQA→MLA、SwiGLU、MoE、采样 | 每个部件解决什么问题、花多少算力、占多少显存 |
| **M2** 推理系统 | KV cache、批处理调度、量化、投机解码、引擎内核 | prefill 算力密集、decode 带宽密集——一切优化都是这个二分的推论 |
| **M3** 训练系统 | 5D 并行、显存账本、通信、容错、SFT/DPO/RLVR | 难点几乎全在系统侧，正好是基建工程师的主场 |
| **M4** PyTorch 工程 | 执行模型、torch.compile、Triton、profiling | 把「知道原理」变成「能修问题」的那一层 |

必须能口算的三个公式：

```
权重显存  = 参数量 × 每参数字节
KV cache = 2 × L × H_kv × d_head × S × B × sizeof(dtype)
训练算力 ≈ 6ND          (N=参数量, D=token 数)
```

## 当前进度：M2 入门阶梯

主题清单可以并列，但入门必须串行。八级，每级带**验收标准**，过不了不往上爬。

| # | 时长 | 阶段 | 验收标准 |
|---|---|---|---|
| 0 | 半天 | 只补 M2 用得上的前置 | 能说清 decode 为什么需要 KV cache，报出线上模型每 token 的 KV 字节数 |
| 1 | 1 天 | 立住 prefill / decode 二分 | 能解释 batch=1 时利用率显示 100%、实际算力却只用了个位数百分比 |
| 2 | 1 天 | 先有测量能力，再谈优化 | 一张自己集群的基线延迟-吞吐曲线，能指出 knee point |
| 3 | 2 天 | KV cache 管理：PagedAttention | 默画出 block table 结构，说清它解决了哪种碎片 |
| 4 | 2 天 | 批处理与调度：continuous batching | 迷你引擎吞吐高于 HF `generate()`，能指着代码说出高在哪 |
| 5 | 1–2 天 | 精读 vLLM V1 源码 | 画出请求生命周期的调用链图 |
| 6 | 2 天 | 扫旋钮，用真机说话 | 一张旋钮效果表，每格带 TTFT / TPOT / 吞吐 |
| 7 | 按需 | 进阶：P/D 分离、KV-aware 路由 | 一页纸的架构改进建议，每条说明改善哪个指标 |

两个刻意的排序决定：

- **测量（2）排在所有优化之前。** 先建立测量能力，之后每学一个技巧当天就能在真机上验证一次，正反馈比按部就班读论文强得多。
- **读源码（5）排在手写迷你引擎之后，不是之前。** 先自己造一遍轮子再看工业级实现，会一路看到「哦这里我当时偷懒了」；顺序反过来只是在抄结构。

## 收藏体检

已有中文资料偏「原理 + 训练 + PyTorch 入门」，覆盖体检结果：

- **最大缺口：M2 推理系统几乎是空的。** 没有推理引擎材料——没有 PagedAttention、没有连续批处理、没有量化与投机解码、没有 vLLM/SGLang 源码。而这恰好是我日常在运维的那层。
- **小缺口一：M4 深水区。** 中文 PyTorch 教程都停在「框架怎么用」，不覆盖 `torch.compile` 内部、Triton、Nsight 归因。
- **小缺口二：训练基础设施与 RL 系统。** 分布式 checkpoint、容错弹性、rollout/训练引擎共存都还没有落点。

被低估的两条：**Ultra-Scale Playbook 中文版**（M3 并行策略最佳单一材料）和 **JAX scaling-book 的 GPU 章**（用 roofline 的语言把硬件、通信、并行策略串成可计算的模型，正好是 M0 和 M3 之间那座桥）。

完整的资料归位表和缺口补充清单见[在线版](https://zhuguangbin.github.io/llm-learning-notes/)。
